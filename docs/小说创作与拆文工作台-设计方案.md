## 1. 项目概述

**小说创作与拆文工作台**（下文简称"工作台"）是一个面向网络小说作者与内容创作者的 **Web 端一体化创作平台**，覆盖「拆文 → 设定 → 大纲 → 正文 → 审稿 → 定稿」的完整创作链路，并通过统一的 **Agent Runtime 抽象层** 接入本地与远程的 AI 能力（LLM 模型服务 + Agent CLI 运行时）。

与 Pagekin 的桌面单机形态不同，本工作台采用 **B/S 架构**：浏览器为交互入口，Node.js 服务端作为"运行时编排中枢"，负责本地 Agent 的自动发现与进程管理、远程服务的接入代理、以及创作数据的持久化。

| 写作 Skill | 导入 SKILL.md，绑定到规划/写稿/审稿/修稿阶段 | ✅ 保留，且本方案扩展为"可执行" Skill |
| 运行侧页 | 任务进行中/历史/诊断，可取消/暂停 | ✅ 保留，升级为"任务中心 + 流式输出" |

### 2.3 Pagekin 的设计优点（继承）

1. **作者主导**：AI 起草 + 用户逐步确认，避免"AI 代笔"失控。
2. **结构化写作流水线**：把长篇写作拆成可管理的阶段，上下文按需装配。
3. **上下文裁剪**：每次只给 AI 相关章节 + 角色 + 世界观 + 前文摘要，而非整本书。
4. **本地优先、隐私可控**：数据不出本机（除非主动调云端）。
5. **可扩展**：多模型配置、Skill 导入、知识库检索。

### 2.4 Pagekin 的局限（本方案改进点）

| 局限 | 本方案改进 |
|------|-----------|
| 仅支持"提示词型" Skill，不能执行脚本/工具 | 引入 **Agent CLI 运行时**，支持真正可执行的多步 Agent 任务 |
| 模型需手动逐个配置，无自动发现 | 增加 **本地 Agent Runtime 自动扫描**（端口/命令/配置三路探测） |
| 桌面单机，难以团队协作 / 远程部署 | 采用 Web 架构，可本机运行也可远程部署 |
| 无统一 Agent 抽象，扩展新 runtime 成本高 | 定义统一 `AgentRuntime` 接口 + Provider 插件机制 |
| 拆文能力相对独立、深度有限 | 将"拆文"提升为一级工作台，与创作链路深度联动 |

## 3. 设计目标与定位

### 3.1 一句话定位

**一个"拆得透、写得顺、AI 能力即插即用"的小说创作与拆文一体化 Web 工作台。**

### 3.2 设计目标

1. **一体化创作流水线**：覆盖拆文、设定、大纲、蓝图、正文、审稿、定稿全链路。
2. **AI 能力即插即用**：本地自动发现可用 Agent Runtime，远程一键配置，统一调度。
3. **本地优先 + 云端可选**：数据默认本地存储，AI 能力可本地可远程，隐私自主。
4. **拆文深度专业化**：不仅仿写，更产出结构、文风、爽点、节奏、人物弧等多维分析，反哺创作。
5. **可扩展、可协作**：模块化架构，支持插件式 Skill/Provider，预留多用户与团队空间。

### 3.3 目标用户

- 网络小说作者（长篇 / 短篇）
- 内容工作室与编辑（拆文、选题、竞品分析）
- AI 短剧编剧（复用拆文 → 大纲 → 剧本链路）

## 4. 核心功能特性

### 4.1 功能全景

```
┌─────────────────────────────────────────────────────────┐
│                    小说创作与拆文工作台                      │
├─────────────────────────────────────────────────────────┤

│  ├ 项目管理      ├ 书名搜索下载  ├ 设定与架构   ├ 本地扫描     │
│  ├ 进度概览      ├ 结构拆解     ├ 章节蓝图     ├ 远程接入     │
│  ├ 版本历史      ├ 文风提取     ├ 正文写作     ├ 能力探测     │
│  └ 导出备份      ├ 爽点/节奏    ├ 审稿修稿     └ 任务调度     │
│                 └ 拆文报告     └ 定稿导出                    │
├─────────────────────────────────────────────────────────┤
│  ⑤ 知识库       ⑥ 任务中心     ⑦ Skill 管理   ⑧ 系统设置     │
│  全文检索       流式输出       导入/绑定     多租户/权限     │

└─────────────────────────────────────────────────────────┘
```

### 4.2 功能特性清单

#### A. 工作区与书房（项目管理）

- 多项目（作品）管理，卡片式概览：进度、字数、定稿章数、角色数、最近编辑时间。
- 项目归档 / 复制 / 导入（兼容 Pagekin 旧项目 JSON 导入）。
- 版本历史：每章历次稿件保留，支持对比与回退。
- 导出：合并 Markdown、分章 Markdown、TXT、EPUB（可选）。

#### B. 拆文工作台（一级模块，核心卖点）

- **书名搜索下载**：输入书名在线搜索，返回候选书目（书名/作者/简介/来源/格式），一键下载为 txt/epub 进入素材库。
- **素材导入**：本地 txt / md / epub / 粘贴正文 / 网页抓取，作为书源下载的补充。
- **结构拆解**：章节切分 → 每章情节单元、冲突、转折、悬念、伏笔。
- **文风提取**：句式长度分布、对话占比、描写风格、高频词、情绪曲线。
- **爽点/节奏分析**：爽点密度时间轴、节奏张弛曲线、钩子命中率。
- **人物与关系**：角色卡自动生成、关系图谱、人物弧光。
- **拆文报告**：可视化单页报告（KPI 带、爽点时间轴、结构树、文风雷达图）。
- **反哺创作**：一键将拆文结论转为"仿写约束"或"新作品设定"，直接进入创作链路。

#### C. 创作工作台

- **设定与架构**：类型 / 受众 / 语言 / 章数；故事前提、角色名单、世界观、情节大纲。
- **章节蓝图**：逐章规划（目标、冲突转折、悬念钩子、出场人物），支持按范围批量生成（单批上限可配置）。
- **正文写作**：单章视图完成「写稿 → 审稿 → 修稿 → 定稿」；段落续写、润色、扩写、改对话、去 AI 味。
- **上下文装配引擎**：章节蓝图 + 相关角色 + 世界观 + 前文摘要 + 上一章全文，按需裁剪。
- **审稿系统**：AI 审稿意见逐条勾选 / 忽略；修稿逐段差异对比确认，不直接覆盖原稿。

#### D. AI Agent Runtime（本地 + 远程）

- **本地自动扫描**：端口探测 + 命令探测 + 配置探测，自动发现可用 Runtime 并展示能力。
- **远程接入**：HTTP / SSE / MCP 协议接入远程 Agent 服务；OpenAI 兼容 + Gemini 原生 + Anthropic 原生。
- **能力探测**：对发现的 Runtime 做健康检查与能力探测（是否支持流式、工具调用、长上下文等）。
- **统一调度**：创作任务通过统一接口派发给指定 Runtime，支持流式回传、取消、超时、重试。

#### E. 知识库

- 参考资料导入（txt / md），本地全文检索 + 可选用向量检索。
- 剧情与伏笔追踪：按章维护主线 / 支线 / 伏笔进度。

#### F. 任务中心

- 任务进行中 / 历史 / 诊断三视图；实时流式输出。
- 取消、暂停、批量暂停、失败恢复候选。

#### G. Skill 管理

- 导入 SKILL.md（提示词型）与执行型 Skill（脚本 / 工具）。
- 绑定到规划 / 写稿 / 审稿 / 修稿阶段。

#### H. 系统设置

- 浅色 / 深色主题，中英文界面。
- 多 Agent Runtime 配置与凭据管理（API Key 加密存储）。
- 预留多用户 / 团队协作（后续里程碑）。

### 4.3 书源搜索与下载（拆文素材获取）

拆解仿写的第一步是"拿到文本"。本模块提供 **书名 → 搜索 → 下载 → 入库** 的完整链路，作为拆文工作台的素材入口。

#### 4.3.1 书源抽象

采用"书源 Provider"插件机制，与 Agent Runtime 抽象层同构：

```typescript
interface BookSource {
  id: string;
  name: string;                  // 书源名（可自定义）
  type: 'catalog' | 'open';      // catalog=目录检索，open=开放库
  priority: number;
  enabled: boolean;
  search(query: string): Promise<BookSearchResult[]>;
  getBookDetail(id: string): Promise<BookDetail>;
  download(id: string, format: 'txt' | 'epub'): Promise<DownloadResult>;
}

interface BookSearchResult {
  id: string;
  title: string;
  author: string;
  source: string;                // 来源书源
  cover?: string;
  intro?: string;
  format: string[];              // 可用格式
  url?: string;
}

interface BookDetail {
  // 继承 BookSearchResult 字段
  chapters?: { title: string; content?: string }[];
  status?: string;               // 连载 / 完结
  wordCount?: number;
}
```

#### 4.3.2 内置书源（优先合规开放来源）

| 来源 | 类型 | 说明 |
|------|------|------|
| Open Library / Internet Archive | open | 公版书籍，免费公开，提供元数据与部分全文 |
| Project Gutenberg | open | 公版文学，txt/epub 免费下载 |
| Google Books API | catalog | 图书元数据检索 |
| 豆瓣读书（元数据） | catalog | 中文图书检索、简介、评分 |
| 自定义书源 | catalog | 用户自行配置的检索规则（类"阅读 App"书源） |

> **合规声明**：工作台默认只内置公版 / 开放来源。对受版权保护的连载网文，搜索下载能力仅用于"用户已合法获取的文本"的本地管理，不内置盗版源；用户自行配置的书源，其内容合规性由用户自负。

#### 4.3.3 搜索下载流程

```
输入书名（可多关键词 + 作者过滤）
      → 并行请求已启用的书源 → 聚合去重（按书名+作者）
      → 前端展示候选（封面/简介/来源/格式/状态）
      → 用户选择 → 下载（服务端代理，进度可看）
      → 解析为统一文本（epub → 章节化文本；txt 编码探测）
      → 入库：进入拆文素材库（deconstruct_source）
      → 触发后续结构拆解
```

#### 4.3.4 关键实现要点

- **下载代理**：由服务端统一下载，避免前端跨域与反爬限制；支持 User-Agent、超时、重试、并发控制。
- **格式归一**：epub 解析（章节拆分）与 txt 编码探测（GBK/UTF-8）统一为内部文本模型。
- **元数据与正文分离**：书目元数据入 SQLite，正文落文件系统。
- **缓存与去重**：按（书名 + 作者 + 来源）幂等，重复导入提示。
- **可选代理配置**：网络受限时支持配置 HTTP 代理。

```
        ┌──────────────────────┼──────────────────────┐
        ▼                      ▼                      ▼
┌───────────────┐    ┌──────────────────┐    ┌──────────────────┐
│  本地 Runtime   │    │   本地 Agent CLI   │    │   远程 Runtime    │
│  Ollama / vLLM │    │  codex / claude   │    │  远程 Agent 服务  │

└───────────────┘    └──────────────────┘    └──────────────────┘
```

### 5.2 架构原则

1. **前后端分离**：前端纯展示与交互，业务逻辑在服务端。
2. **领域驱动**：拆文、创作、知识库为独立领域模块，边界清晰。
3. **Provider 插件化**：Agent Runtime 通过统一接口接入，新增 runtime 只需新增 Provider 实现。
4. **流式优先**：AI 输出统一走 SSE 流式回传，改善长文本生成体验。
5. **本地优先**：默认数据落地本地 SQLite + 文件系统；云端可选。

## 6. AI Agent Runtime 抽象层（核心）

### 6.1 设计目标

将"AI 能力"抽象为统一的 `AgentRuntime` 接口，屏蔽底层差异，使得：

- 本地 Ollama 与远程 DeepSeek 对上层无差别；
- 既能做**单次模型对话**（LLM），也能驱动**多步 Agent 任务**（Agent CLI）；
- 新增 runtime 零侵入（实现 Provider 接口即可）。

### 6.2 Runtime 三分法

| 类型 | 形态 | 交互方式 | 典型代表 |
|------|------|---------|---------|
| `llm` | 模型推理服务 | HTTP（OpenAI 兼容 / Gemini 原生 / Anthropic 原生） | Ollama、vLLM、LM Studio、DeepSeek、OpenAI、Claude、Gemini |
| `agent-cli` | 本地 Agent CLI 进程 | 子进程 stdio（spawn） | codex、Claude Code CLI、Gemini CLI、aider、OpenCode、Goose |
| `remote` | 远程 Agent 服务 | HTTP / SSE / WebSocket / MCP | 自建 Agent 服务、远程 MCP Server |

### 6.3 统一接口定义

```typescript
// 能力标识
type AgentCapability =
  | 'chat'            // 基础对话/生成
  | 'stream'          // 流式输出
  | 'tool-call'       // 工具调用（Function Calling / MCP）
  | 'agent-task'      // 多步自主任务
  | 'vision'          // 多模态图片理解
  | 'long-context'    // 长上下文
  | 'embedding';      // 向量嵌入

// Runtime 元信息
interface AgentRuntimeInfo {
  id: string;                    // 唯一标识
  name: string;                  // 显示名
  type: 'llm' | 'agent-cli' | 'remote';
  provider: string;              // Provider 名，如 'ollama' | 'codex' | 'deepseek'
  baseUrl?: string;              // 远程地址（llm/remote）
  command?: string;              // CLI 命令（agent-cli）
  models?: string[];             // 可用模型列表
  capabilities: AgentCapability[];
  status: 'scanning' | 'available' | 'unavailable' | 'error';
  health?: { latencyMs: number; lastCheck: number };
}

// 统一 Runtime 接口（Provider 实现）
interface AgentRuntime {
  info(): Promise<AgentRuntimeInfo>;
  listModels(): Promise<string[]>;
  chat(req: ChatRequest): Promise<ChatResponse>;              // 单次对话
  streamChat(req: ChatRequest, onChunk: (c: ChatChunk) => void): Promise<void>; // 流式
  runTask?(task: AgentTask, onEvent: (e: TaskEvent) => void): Promise<TaskResult>; // Agent 任务
  cancel?(taskId: string): Promise<void>;
  healthCheck(): Promise<{ ok: boolean; latencyMs: number }>;
}

interface ChatRequest {
  messages: Message[];
  model?: string;
  temperature?: number;
  maxTokens?: number;
  tools?: ToolSchema[];
  system?: string;
}

interface AgentTask {
  id: string;
  instruction: string;         // 自然语言任务指令
  context?: string;            // 附带上下文
  cwd?: string;                // 工作目录
  maxTurns?: number;
  timeoutMs?: number;
}
```

### 6.4 本地自动扫描（核心机制）

扫描采用**三路并行探测 + 能力验证**，由服务端启动时触发，也可手动刷新。

#### 6.4.1 端口探测（发现 `llm` 型本地服务）

维护一张"已知本地推理服务"指纹表，对每个 `host:port` 做 TCP 连接 + 健康端点探测：

| 服务 | 默认地址 | 健康/模型端点 |
|------|---------|--------------|
| Ollama | `127.0.0.1:11434` | `GET /api/tags` |
| LM Studio | `127.0.0.1:1234` | `GET /v1/models` |
| vLLM | `127.0.0.1:8000` | `GET /v1/models` |
| llama.cpp | `127.0.0.1:8080` | `GET /v1/models` |
| text-generation-webui | `127.0.0.1:5000` | `GET /v1/models` |
| LocalAI | `127.0.0.1:8080` | `GET /v1/models` |
| Xinference | `127.0.0.1:9997` | `GET /v1/models` |

> 端口冲突时，命中端点返回合法 JSON 才认定为该服务；否则降级为"未知 OpenAI 兼容服务"。

#### 6.4.2 命令探测（发现 `agent-cli` 型）

在系统 `PATH` 中查找已知 CLI 可执行文件（Windows 用 `where`，Unix 用 `which`）：

| CLI | 探测命令 | 能力 |
|-----|---------|------|
| codex | `codex --version` | agent-task / tool-call |
| Claude Code | `claude --version` | agent-task / tool-call |
| Gemini CLI | `gemini --version` | agent-task / tool-call |
| aider | `aider --version` | agent-task |
| OpenCode | `opencode --version` | agent-task |
| Goose | `goose --version` | agent-task |

命中后记录 `command` 与路径，`agent-cli` 型 Runtime 通过子进程 spawn 驱动。

#### 6.4.3 配置探测（发现已配置但未运行的 Runtime）

读取已知配置目录，识别"已安装但未启动"的 Runtime，标记为 `unavailable` 并给出启动提示：

- `~/.ollama`、`~/.codex`、`~/.claude`、`~/.gemini`、`~/.aider.conf.yml` 等。

#### 6.4.4 能力验证

发现候选后，执行一次轻量健康检查与能力探测：

- `llm`：请求 `/v1/models` 判断模型列表；可选用最小对话测试判断流式 / 工具调用。
- `agent-cli`：`--version` 成功即判定可用；`tool-call` 能力由 CLI 类型静态映射。
- `remote`：握手 + 可选 ping。

扫描结果落库缓存，前端"AI 运行时"面板实时展示（可用 / 未安装 / 可启动）。

### 6.5 远程接入

- **HTTP/SSE 代理**：统一通过服务端代理转发到远程 Agent 服务，前端不直接暴露凭据。
- **协议适配**：OpenAI 兼容（`/v1/chat/completions`）、Gemini 原生、Anthropic 原生（`/v1/messages`）。
- **MCP 接入**：支持将远程 MCP Server 注册为工具源，供 `llm` 型 Runtime 的工具调用使用。
- **凭据管理**：API Key 加密存储（AES-GCM），仅服务端可读。

### 6.6 运行时调度

- **任务队列**：创作/拆文任务进入队列，按 Runtime 可用性派发。
- **流式回传**：统一 SSE 通道，`streamChat` / `runTask` 事件实时推送。
- **超时与取消**：支持任务超时、手动取消、`agent-cli` 进程强杀。
- **降级策略**：指定 Runtime 不可用时，可配置自动降级到备用 Runtime。

## 8. 数据模型

### 8.1 核心实体（关系概览）

```
Novel (作品) 1 ──── n Chapter (章节)
   │                  │
   │ 1                │ n
   │                  └─────── Draft (草稿/定稿，含版本)
   │
   ├── n Character (角色)
   ├── n WorldItem (世界观条目)
   ├── n Blueprint (章节蓝图)
   ├── n PlotThread (剧情/伏笔线)
   ├── n KnowledgeDoc (知识库文档)
   └── n DeconstructReport (拆文报告)

Runtime (Agent 运行时) n ──── n Skill (Skill)
```

### 8.2 关键表结构

```sql
-- 作品
CREATE TABLE novel (
  id          TEXT PRIMARY KEY,
  title       TEXT NOT NULL,
  genre       TEXT,              -- 类型
  audience    TEXT,              -- 受众
  language    TEXT DEFAULT 'zh',
  total_chapters INTEGER,
  words_per_chapter INTEGER,
  premise     TEXT,              -- 故事前提

  status      TEXT,              -- planning / writing / done
  created_at  INTEGER,
  updated_at  INTEGER
);

-- 章节
CREATE TABLE chapter (
  id       TEXT PRIMARY KEY,
  novel_id TEXT NOT NULL,
  seq      INTEGER,              -- 序号
  title    TEXT,
  blueprint_id TEXT,             -- 关联蓝图
  status   TEXT,                 -- draft / reviewing / revising / final
  summary  TEXT,                 -- 摘要（供上下文装配）
  content  TEXT,                 -- 当前正文
  created_at INTEGER,
  updated_at INTEGER
);

-- 稿件版本
CREATE TABLE draft (
  id         TEXT PRIMARY KEY,
  chapter_id TEXT NOT NULL,
  version    INTEGER,
  kind       TEXT,               -- draft / review / revise / final
  content    TEXT,
  created_at INTEGER
);

-- 章节蓝图
CREATE TABLE blueprint (
  id        TEXT PRIMARY KEY,
  novel_id  TEXT NOT NULL,
  chapter_seq INTEGER,
  goal      TEXT,                -- 小目标

  hook      TEXT,                -- 悬念钩子

);

-- 角色
CREATE TABLE character (
  id       TEXT PRIMARY KEY,
  novel_id TEXT NOT NULL,
  name     TEXT,
  setting  TEXT,                 -- 基础设定
  state    TEXT,                 -- 当前状态
  relations TEXT                 -- 关系(JSON)
);

-- 拆文报告
CREATE TABLE deconstruct_report (
  id        TEXT PRIMARY KEY,
  novel_id  TEXT,

  style     TEXT,                -- 文风(JSON)
  rhythm    TEXT,                -- 爽点/节奏(JSON)
  characters TEXT,               -- 人物(JSON)
  report_md TEXT,                -- 渲染用报告
  created_at INTEGER
);

CREATE TABLE runtime (
  id         TEXT PRIMARY KEY,
  name       TEXT,
  type       TEXT,               -- llm / agent-cli / remote
  provider   TEXT,
  base_url   TEXT,
  command    TEXT,
  config     TEXT,               -- 加密配置(JSON)
  capabilities TEXT,             -- 能力(JSON)

  created_at INTEGER

CREATE TABLE book_source (

  provider TEXT,                 -- 内置 provider 名或自定义

  created_at INTEGER
```

## 9. 关键交互流程

### 9.1 启动时本地 Runtime 自动扫描

```
服务端启动 → Scanner 三路并行探测（端口/命令/配置）
        → 对候选执行健康检查 + 能力验证
        → 结果落库 → 前端"AI 运行时"面板 SSE 推送更新
        → 用户选择默认 Runtime → 创作任务派发
```

### 9.2 拆文流程

```
书名搜索下载 / 导入素材 → 章节切分（本地） → 逐章 AI 拆解（流式）
        → 结构/文风/爽点/人物 多维度聚合
        → 生成拆文报告（可视化）
        → 一键转为"仿写约束"或"新作品设定"
```

### 9.3 创作流程（单章）

```
选择章节 → 上下文装配（蓝图+角色+世界观+摘要+上章全文）
        → 写稿（AI 流式生成） → 审稿（AI 意见逐条）
        → 修稿（逐段差异对比） → 定稿（版本存档）
```

## 14. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 本地 Runtime 端口/命令差异大 | 扫描误判 | 指纹表可配置；命中后做端点内容校验，失败降级"未知服务" |
| agent-cli 输出格式不稳定 | 解析失败 | 按 CLI 类型适配解析器；保留原始日志用于诊断 |
| 长文本生成耗时 | 体验差 | SSE 流式输出 + 任务取消/暂停 + 超时控制 |
| 云端 API Key 泄露 | 安全 | 服务端加密存储，前端不落 Key；统一代理转发 |
| 上下文超长 | 成本与质量下降 | 上下文装配引擎按需裁剪，摘要 + 关键片段策略 |
| 书源搜索下载的版权与来源合规 | 法律风险 | 默认仅内置公版/开放源；不内置盗版源；自定义书源合规性由用户自负；下载仅用于合法已获取文本的本地管理 |
| 书源不稳定/反爬 | 搜索下载失败 | 服务端代理 + UA/重试/超时；多书源并行 + 失败降级；结果缓存 |
| 单机 SQLite 并发 | 多用户瓶颈 | 单机优先；预留迁移到 PostgreSQL 的仓储接口 |
